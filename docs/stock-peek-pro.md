# Stock Peek Pro — 통합 제품·기술 설계 v1.0

- 작성 기준: 2026-11-22
- 상태: **설계 문서** (실제 결제·뉴스 수집·LLM·알림 출시를 의미하지 않음)
- 대상: Electron(Windows/macOS) + React + `electron-store` + Cloudflare
- 관련: [기존 AI 리포트 기술 실험](ai-report.md) · [IPC 계약](ipc.md) · [프로젝트 규칙](../AGENTS.md)

## 1. 제품 정의와 범위

**문제:** 현재 관심 종목과 수량·평단은 확인할 수 있어도, 사용 중 무엇을 추가/삭제했는지, 보유정보가 언제 어떻게 바뀌었는지, 이후 기업·산업에서 어떤 새로운 일이 있었는지 되짚기 어렵다.

**제공 가치:** 이용자가 축적한 **관심/보유정보 변화 이력** + **선택적 투자 관점** + **출처가 확인된 최신 뉴스·공시**를 결합하여, 이전 분석 이후 달라진 점과 추가로 확인할 사항을 A4 한 장에 정리한다. 가격 알림은 별개의 반복 확인 수요를 해결한다.

**비목표:** AI 매수/매도 지시, 목표주가, 수익률 예언, 실제 거래 자동 추정, 증권사 계정 연동, 글로벌 채팅, 뉴스 포털, 자동매매. 정교한 수익률/성과 평가는 검증된 거래 원장·시세·환율이 확보되기 전에는 제공하지 않는다.

| 구분 | 기능 | 결정 |
|---|---|---|
| Free | 기존 주가 위젯·보유정보 설정 | 유지, 기존 기능 유료 전환 없음 |
| Free | 관심 종목 추가/삭제 및 보유정보 *수정 이력* | 새 버전 이후 로컬 축적 |
| Free | 선택적 종목 메모/투자 관점 | 로컬 저장, 수정/삭제 가능 |
| Pro(가격 별도) | 가격 이상/이하 도달 알림 | 로컬 OS 알림; 데이터 이용권 및 과금 정책 미확정 |
| AI 크레딧 | 개인 활동·보유 구성·투자 관점·최신 자료 분석 | 1회 생성 = 1크레딧 |
| AI 크레딧 | A4 세로 1장 PDF | 생성 결과 저장/재다운로드에 추가 차감 없음 |

### 1.1 확정 상품 정책

- **990원(부가세 포함 가정) / 10회**: *월 구독이 아닌 일회성 충전형*. 일일 횟수 제한 없음.
- 보고서 1건 생성 = 1크레딧; 1건당 최대 **관심 종목 5개** 선택.
- **서버에서 검증된 리포트 생성·저장 성공 시에만 최종 차감**. 타임아웃·자료 제공 실패·LLM 검증 실패는 미차감/예약 해제. 로컬 PDF 저장 오류는 이미 생성된 리포트를 무료로 재출력하여 복구하며 추가 차감하지 않는다.
- 동일 요청 중복 제출은 하나의 작업으로 수렴; 성공 후 PDF 재다운로드 무과금.
- 잔여 크레딧은 서버가 진실원천(source of truth). 추가 구매는 잔액 가산.
- **유효기간·환불·미사용 크레딧 처리·부분 사용 후 환불·결제 수수료·세금·소비자 고지**는 결제사 계약/법률 검토 후 최종 확정한다. 임의로 영구 소멸 없음/무기한 보장이라 홍보하지 않는다.
- 뉴스/시세 라이선스와 원가 검증 전 **유료 결제 공개 금지**. 990원은 확정한 *가격 가설*이며 채산성이 검증된 가격은 아니다.

### 1.2 보고서 용도 분리

- **일간/요청 시**: 이전 보고서 대비 새로운 확인 사실, 관련 종목·투자 관점에 미치는 의미.
- **이력 중심 분석**: 실제 사용 기간 동안 관심 목록·보유정보의 변화를 요약. 매일 새 변화가 없는 경우에도 허위 사건을 만들지 않는다.
- **실제 거래 분석**은 사용자 명시 거래 원장을 추가하기 전까지 하지 않는다.

## 2. 사용자 경험(UX)

### 2.1 Free: 기록 축적

기존 `watchlist:add` / `watchlist:remove` / `watchlist:update-holding` 동작 성공 시 변경 전후 스냅샷을 바탕으로 변경 이벤트를 기록한다. 기록 활성화·보관 기간·내보내기·초기화에 대한 고지를 제공하고 사용자가 관리할 수 있게 한다. 단순 UI 정렬·시세 갱신은 투자 활동 이력으로 기록하지 않는다.

기존 이용자의 과거 이력은 알 수 없다. 업그레이드 당시 스냅샷을 별도 `baseline_imported`로 표시하며, 기존에 매수했다고 **추정하지 않는다**.

### 2.2 AI 분석 생성

1. 앱에서 **AI 분석** 선택 → 기존 관심 목록 자동 채움.
2. 종목 1–5개 선택. 보유정보 포함 체크박스는 **기본 꺼짐**.
3. '나의 투자 관점'(자유 입력, 선택)과 투자 기간/중점 요소(선택)를 저장·수정할 수 있다.
4. 데이터 전송 미리보기: 종목 코드, 옵션에 따라 수량/평단, 기간 내 활동 이력, 사용자 작성 관점만 열거.
5. 요청 전 뉴스/공시 데이터 범위·최근성·부족한 자료를 안내. 중요한 자료가 없는 날에는 빈약한 보고서를 억지로 만들지 않고 간략 미리보기/생성 취소 선택을 제공.
6. 실행 → 생성 상태 표시 → 보고서 화면에서 미리보기 및 A4 PDF 저장. 반복 다운로드 무차감.
7. **생성 실패** 시 오류 종류를 명확히 표시하고 크레딧 예약 해제; 생성 성공 이후 발생한 로컬 PDF 저장 오류는 동일 리포트를 무료로 재출력한다. 내용 검증 실패 보고서를 성공 처리하지 않는다.

### 2.3 가격 알림

- 카드의 종 모양 아이콘 → 종목별 목표 가격 이상/이하, 1회 알림 설정/수정/삭제.
- 비교 가격의 통화·시장·출처·시세 기준 시각·지연 가능성을 표시.
- 기본: 설정 직후 이미 임계값을 넘었다면 **즉시 발송하지 않고**, 임계값 반대편의 유효 가격을 확인한 뒤 목표 측으로 다시 진입하는 첫 교차에 발송. 정책은 안내한다.
- 앱이 실행 중이고 패널이 숨겨져도 작동; **앱 종료·PC 절전·네트워크 장애 중에는 실시간 알림 보장 없음**.
- 초단위 거래소 호가 알림이 아니라 **주기적 조회 기반 알림**으로 표현. 네트워크 복귀 후 과거 데이터를 근거로 소급 알림하지 않는다.

## 3. 데이터 모델

### 3.1 로컬(Free): 사용자 이력

기존 `watchlist` electron-store의 **현재 상태**와 별개의, 버전 명시된 추가 전용 이벤트 로그를 둔다.

```json
{
  "schemaVersion": 1,
  "eventId": "uuid",
  "occurredAt": "2026-11-22T06:00:00.000Z",
  "type": "holding_edited",
  "stock": {"market": "US", "symbol": "NVDA"},
  "before": {"quantity": 3, "avgPrice": 100},
  "after": {"quantity": 5, "avgPrice": 108},
  "origin": "user",
  "semantic": "holding_snapshot_change"
}
```

종류: `watchlist_added`, `watchlist_removed`, `holding_edited`, `baseline_imported`, `thesis_edited`(자유 입력은 민감할 수 있으므로 변경 이력 보존보다 현재 값 저장을 기본값으로 고려), `transaction_recorded`(향후 명시적 거래 기록에만 사용).

**절대 추론 금지:** `watchlist_removed ≠ sell`, `holding_edited ≠ buy/sell`, `avgPrice ≠ 체결 가격`. 투자 수익률·매수 타이밍·승률·실현손익을 이 기록에서 추정하지 않는다.

로컬 이력 저장은 관심 목록 저장 성공과 결합되어야 한다. Electron Store가 복수 파일 원자적 트랜잭션을 보장하지 않는 문제를 대비하여 **이벤트 ID 기반 멱등성, 단일 쓰기 직렬화, 재시작 복구·스냅샷 재조정**을 설계한다. 실제 구현에서는 SQLite 같은 단일 트랜잭션 저장소 도입과 electron-store 일관성 보존 비용을 비교해 선택한다. 이벤트 삭제·내보내기·백업 정책 필수.

### 3.2 로컬: 투자 관점

```json
{
  "thesisVersion": 1,
  "text": "AI 설비투자 확대로 메모리 수요가 증가한다고 본다. 실제 수주와 이익률을 중시한다.",
  "horizon": "long",
  "focus": "fundamentals",
  "updatedAt": "2026-11-22T06:00:00.000Z"
}
```

사용자가 입력한 관점은 **가설**이고, 외부 검증 사실과 구분한다. 반대 근거도 함께 탐색하여 확증편향을 완화한다. 입력하지 않아도 리포트 생성 가능.

### 3.3 서버: 크레딧·생성 작업·자료

D1 권장 논리 테이블:
- `users` / `devices`: 로그인 식별 또는 기기 바인딩 최소 정보, 인증 갱신·분실 복구 정책.
- `credit_ledger`: 적립(확인된 결제)/예약/사용/해제/환불 조정의 **불변 원장**. 모든 움직임은 고유 ID.
- `orders`: 결제사 주문 ID, 통화·금액, 검증된 webhook 이벤트 ID, 상태.
- `analysis_jobs`: 사용자 ID, `idempotency_key`, 요청 hash, 상태 `pending|processing|succeeded|failed`, 예약 크레딧, 오류, 생성된 report ID.
- `reports`: 렌더링용 검증된 구조화 결과, 자료 스냅샷 해시, 이전 보고서 참조, TTL/보존 정책.
- `evidence`: 공급자 ID, 기업 식별자, 발행 시각, 수집 시각, 원본 링크, 이용권·검증 수준.
- PDF 파일은 로컬 저장이 기본. 서버 보관이 필요하면 R2를 선택하되 **암호화·접근제어·기간제한**이 선행되어야 한다.

**필수 불변식:** 잔액은 음수가 될 수 없음; 같은 결제 webhook은 한 번만 적립; 한 idempotency key에 성공 보고서는 최대 하나; 실패/취소는 잔액 감소 없음; 중복 다운로드는 차감 없음. 예약 TTL 만료 시 상태조정 작업으로 복구한다. 단순 "잔액 확인 후 UPDATE" 경쟁 조건을 피하려면 D1 트랜잭션성 배치/조건부 UPDATE와 원장 일관성 검사를 사용한다.

## 4. 정보 수집 및 분석

### 4.1 데이터 출처

| 데이터 | 1차 출처 | 원칙 |
|---|---|---|
| 관심/수정 이력 | 로컬 활동 로그 | 실제 행위만 기록, 거래로 해석 금지 |
| 보유 정보 | 사용자 로컬 입력 | 실행 시 명시 동의로만 전송 |
| 기업/공시 | 한국 OpenDART, 미국 SEC EDGAR | 회사 식별자 매핑, 접수번호·보고기간 보존 |
| 기업 재무·IR | 공시/XBRL/기업 공식 IR | 숫자·기간은 코드가 파싱/계산 |
| 최신 뉴스 | 상업적 분석·요약을 허용한 공급자 | 이용권 확인, 제목·URL·일시·원문 활용 범위 분리 |
| 시세/환율 | 재배포·상업 사용이 허가된 공급자 | 권한 없으면 평가손익/평가비중 계산 생략 |

초기 **심층 정보 대상은 한국·미국 상장기업**. 일본·인도·사우디는 기존 위젯 이용을 유지하지만 리포트 자료 검증 수준이 다르면 미지원/부분지원임을 표시. ETF·ADR·합병/상장폐지/티커 변경·동명 기업은 종목 코드만으로 임의 연결하지 않는다.

### 4.2 분석 파이프라인

```text
Local watchlist + event history + optional holdings/thesis
  → request preview & consent
  → authenticated Worker (schema, entitlement, quota, idempotency validation)
  → official filings + rights-cleared news + stored previous-report snapshot
  → entity mapping / dedup / article freshness / source quality
  → deterministic stats (changes, counts, cost basis by currency)
  → LLM generates structured JSON (facts vs hypotheses; pro/con evidence)
  → server-side schema + citations + numeric + evidence-level validation
  → reserved credit settlement + report persisted
  → Electron separate report viewer → printToPDF(A4) → local save
```

**변화 기준:** `previousReportAt` 또는 최초 사용 기준시각과 현재 자료 시각의 차이. 72시간 고정 범위만으로는 일주일 만에 재방문한 사람의 변화를 누락하므로 **최근 보고서 시점 이후 + 상한 기간(예: 30일)**으로 확장. 뉴스 중복은 콘텐츠 단위 및 동일 사건 병합 처리하고, 정정 공시/후속 사건은 명시적으로 연결한다.

**뉴스 제목은 본문 내용의 증거가 아니다.** 원문이 합법적으로 제공되지 않으면 "기사가 발행됨" 이상을 단정하지 않는다. 사용자 관점과 맞는 기사만 편향 선별하지 않는다. 데이터 제공 장애 시 새 소식이 없다고 거짓 표시하지 않는다(자료 없음과 조회 실패 분리).

### 4.3 수치와 분석 권한

- 보유원가 = 수량 × 평균매입가(종목 통화). 다통화 원가를 단순 합산하지 않는다.
- 평가액/손익/포트폴리오 비중은 **신뢰 가능한 해당 시점 시세 + 환율**이 모두 있을 때만 계산; 없으면 관련 수치 생략하고 계산 불가 사유 표기.
- 포트폴리오 관점은 사용자 제공 해석 맥락일 뿐 금융 목표·위험 성향을 임의 추론하지 않는다.
- LLM은 계산기·데이터 소스가 아니라, **검증된 사실에 대한 설명기**. 임의 숫자/인용/목표주가/매매 지시 거부.
- 근거 URL의 HTTPS 형식만 확인하는 것은 출처 신뢰성 검증에 불충분하다. 공식 도메인 또는 검증된 공급자 레지스트리를 사용.
- 생성 결과는 JSON Schema 기반 검증 후 HTML escaping. 외부 기사·공시 내용의 프롬프트 인젝션을 지시로 취급하지 않는다.

## 5. A4 PDF 1장 규격

**페이지:** A4 portrait, 기본 언어 UI와 일치, 판독 가능한 글자 크기와 충분한 여백. 레이아웃 실패 시 조용히 내용을 잘라내거나 글자를 무한정 축소하지 않고 사용자에게 실패 처리/요약 재시도.

| 영역 | 분량 가이드 | 내용 |
|---|---:|---|
| 헤더 | 10% | 생성 시각, 분석 종목 1–5개, 데이터 신선도 |
| What Changed | 30% | 이전 분석 이후 중요 변화 최대 3건, 사건 시각, 출처 |
| Why It Matters | 25% | 사용자 투자 가설과의 관계(근거 강화/약화/불확실), 반대 근거 |
| My Portfolio | 20% | 관심·보유정보 **변경 기록**, 선택적 자산 구성과 영향 |
| What to Watch | 10% | 이후 확인할 지표 2–3개와 가능한 확인 시점 |
| 출처·한계 | 5% | 자료 URL/접수번호, 시각, 누락 정보 및 비자문 고지 |

실제 정보 밀도에 따라 구성 비중은 조정 가능. **매일 똑같은 기업 소개와 일반론으로 채우지 않는다**. 이전 분석 이후 새로운 근거가 없으면 그 사실을 명시한다. 개인 활동 데이터에도 변화가 없고 신뢰할 새 정보도 없다면 저가치 생성 경고와 취소 옵션을 제공한다.

PDF는 복사가능한 텍스트·클릭 가능한 출처 링크 포함. 저장된 PDF와 report JSON은 최신 뉴스/공시 업데이트에 따라 자동 변조하지 않고 생성 시점 스냅샷 유지.

## 6. 가격 알림 아키텍처

현재 `src/main/index.js`의 `setTarget()`는 패널 숨김 시 `stopPolling()`을 호출한다. **기존 polling에 알림 평가만 덧붙이면 숨김 상태에서 작동하지 않는다.**

변경 설계:
- `stockService`: UI 표시 갱신과 알림용 백그라운드 갱신의 *구독 수요*를 분리. 같은 공급자 호출·캐시·`refreshCoordinator`를 공유한다.
- `alertEngine`: 설정/armed/triggered 상태기계. **신규 유효 시세가 반대측→목표측으로 교차**할 때만 발송. `stale`, 오류, 잘못된 통화, 시간 미확인, 역행하는 시각 무시.
- `alertStore`: 조건·시세 관측 상태·발송 ID를 로컬에 유지. 재시작 후 중복 차단.
- `Notification`: Windows/macOS 네이티브 알림, OS 권한 제한 및 테스트 경로 고려.
- 기본 숨김 상태 갱신은 장중 예: 60초(기술 정책, SLA 아님); UI 표시 시 기존 단기 조회와 중복되지 않게 통합. 야간·휴장·절전·네트워크 복귀 정책 및 국가별 시차 검증.
- 기존 Naver/Yahoo의 상업적 사용 권한이 확정되지 않았으므로 **유료 알림 정식 출시의 선행조건은 허용된 시세 소스 확보**.

가격 알림 Pro 라이선스 가격은 **미확정**. AI 크레딧 잔액과 가격 알림 이용권을 같은 개념으로 혼합하지 않는다.

- `POST /v1/payments/webhook`: 서명·재전송·주문 ID 검증 후 적립(클라이언트 호출 신뢰 금지).

- `POST /v1/reports/:id/export-token`은 서버 PDF를 사용하는 경우에만 필요; 초기에는 로컬 PDF 출력.

**최소 요청 데이터**: 선택한 종목 식별자 + 언어 + 명시 동의한 활동 이벤트 요약·보유정보·투자 관점. 개인 계좌번호·증권사 비밀번호·인증키·전체 로컬 파일·무관한 행동 로그는 전송 금지. HTTP 헤더/로그/오류 메시지에 보유정보와 투자 가설이 남지 않도록 하며 요청 크기와 기간 제한 적용.

- OpenDART 키는 `DART_API_KEY`, OpenRouter 키는 `OPENROUTER_API_KEY` 환경변수에만 설정한다. 기본 라우팅 모델은 `anthropic/claude-sonnet-5.5`이며, 라이브 연결 및 비용 검증 전까지 운영 유료 분석으로 취급하지 않는다.
- P4는 **부분 구현**이다. 최신 뉴스 연동, 본문/XBRL 검증, 직전 리포트 대비 의미 있는 변화, 인증된 Worker API, 운영 데이터 접근 통제는 남아 있다.

### P5 리포트 출력·앱 연결 (운영자 베타, 2026-11-25)

- `src/shared/reportClient.js`: 운영자 PC 환경변수(`STOCKPEEK_ANALYSIS_TOKEN`, 선택 `STOCKPEEK_ANALYSIS_URL`)로만 켜지는 분석 API 클라이언트. 토큰은 앱 번들·저장소에 넣지 않는다. 미설정이면 기존 P3 미리보기 화면과 같다.
- main이 로컬 저장소에서 요청을 다시 만든 뒤 `eFetch`로 `POST /api/analyze`에 보낸다(Electron `net.fetch`는 `Origin` 헤더를 보내지 않아 Worker의 브라우저 차단에 걸리지 않음을 확인). 지원 시장 US·KR, 본문 12KB 상한을 보내기 전에 검사한다.
- 응답 재검증 후 `ai-reports` 로컬 저장소에 스냅샷으로 보관(최신 20개). 보기·PDF 저장·삭제는 서버를 다시 부르지 않는다.
- `src/shared/reportHtml.js`: 4개 언어, 아랍어 RTL, 그레고리력 날짜, 공시 메타데이터 근거 수준 표기, 자료 미수집 종목 표기. JavaScript 없는 정적 문서와 CSP.
- `src/main/reportWindow.js`: 별도 보기 창(JavaScript 꺼짐, 링크는 기본 브라우저), 숨김 창 `printToPDF(A4)`. 페이지 수를 세어 1장을 넘으면 촘촘한 배치로 한 번 더 시도하고, 그래도 넘으면 자르지 않고 `ERR_REPORT_OVERFLOW`.
- 검증: 단위 테스트(`tests/reportClient.test.mjs`, `tests/reportArchive.test.mjs`), Linux Electron에서 모의 API로 생성→보관→보기→삭제 확인. 모든 필드를 최대 길이로 채운 극단적 한국어·일본어 리포트는 A4 1장을 넘어 `ERR_REPORT_OVERFLOW`가 난다. Windows·macOS 실제 글꼴에서의 PDF 확인은 아직 하지 않았다.
- 남은 것: 서버 요약문이 `locale`과 무관하게 영어(`metadataOnlyReport`)인 점, 인증·크레딧 원장·결제(P6), 일반 사용자 공개 전 개인정보 처리방침 웹페이지 갱신.

### Cloudflare Pages 테스트 API (미배포)

- `stockpeek-proxy/`에 자체 Pages Functions 프로젝트 코드 추가. `GET /api/health`, 운영자 인증이 필요한 `POST /api/analyze`를 제공한다. 코드만 등록했으며 **Cloudflare 배포·실제 API 실행 성공을 의미하지 않는다**.
- `ANALYSIS_ENABLED=1` 명시 설정, 별도 `ANALYSIS_TEST_TOKEN` Secret, `ANALYSIS_DB` D1 일일 쿼터가 모두 있어야 호출된다. 브라우저 Origin 요청 차단, 미설정/무인증 요청 차단, 12KB 요청 상한 적용.
- Cloudflare Pages `stockpeek-proxy` 프로젝트의 실제 Git 연결·루트/빌드/기존 Functions 구성을 확인한 뒤에만 적용. `stockpeek-proxy/README.md`에 바인딩/배포/한계 설명.
- 이 테스트 API는 사용자 계정/결제/크레딧/저장된 보고서가 없으므로 Electron 일반 사용자에게 연결하지 않는다. D1 일일 **테스트 한도는 유료 크레딧이 아니다**.

## 10. 개발 순서와 합격 기준

| 단계 | 산출물 | 합격 기준 |
|---|---|---|
| P0 | 데이터·결제·법적 선행검토 | 가격/뉴스/공시/시세 사용권 범위와 예상 원가 기록; 미확인 항목 기능 게이트 |
| P1 | Free 활동 이력·내보내기 | **코드 구현**: 추가/삭제/수정 중복 방지, 로컬 JSON 내보내기/삭제, 단위 테스트. 앱/OS 통합 검증은 별도 필요 |
| P2 | 가격 알림 로컬 엔진/UX | **기초 로직 구현**: 패널 숨김 중 감시, stale 차단, 1회 발송, 로컬 상태 저장. OS·장중/장외 통합 검증은 추가 필요 |
| P3 | 투자 관점·AI 분석 요청 계약 v2 | 선택 정보만 서버 전송, 이전 분석 대비 변화, 이력 기반 수치 검증 |
| P4 | 공시/뉴스 수집·LLM 근거 검증 | **부분 구현**: SEC/OpenDART 메타데이터 수집 및 출처·ID 검증. 뉴스 라이선스·공시 본문/XBRL·LLM 실사용 검증은 미완료 |
| P5 | PDF 출력/품질 검증 | **운영자 베타 구현**: A4 실제 1페이지 검사, 링크/텍스트 복사, KO/EN/JA/AR 렌더 테스트, PDF 재저장. Windows/macOS 실기기 확인 필요 |
| P6 | 인증·10크레딧 원장·결제 | webhook 위변조/중복/환불, 요청 병렬·재시도, 실패 무과금, 사용자 간 격리 |
| P7 | 제한적 베타/원가 검증 | 동일 자료 반복/뉴스 없을 때 품질, 1건당 최악 비용, 반복 사용률·결제 전환 확인 |

P0의 조사와 P1–P3의 로컬 기술 구현은 병행 가능하나 **라이선스 확인 전 과금/광고 문구에 '실시간 정확한 주가 알림' 등 보장 금지**. 모든 단계에서 `npm run lint`, `npm run check:i18n`, `npm test`, `npm run build`, Windows/macOS 동작 점검을 시행한다.

### 우선 검증할 제품 가설

1. 실제 사용자 이력을 *기록만* 해도 다시 확인하고 싶은 가치가 있는가?
2. "최근 자료 + 내 투자 관점 + 사용 이력"의 PDF가 일반 AI 뉴스 요약보다 유용한가?
3. 990원/10회에서 재구매가 발생하는가? 10회를 모두 사용한 최악 원가에도 마진이 남는가?
4. 가격 알림에서 지연·장외·절전 한계를 명시해도 유의미한 수요가 있는가?

**최종 운영 원칙:** 억지로 PDF 내용을 채우지 않는다. 새 사실이 없으면 없다고 말하고, 실패는 무과금 처리한다. 개발 완성보다 **재사용/재구매와 분석 신뢰도**를 우선 평가한다.


### Worker 프록시 소스 통합 (배포 전)
- 실제 운영 `stockpeek-proxy.sngmng.workers.dev`는 별도 Cloudflare Worker이며, 기존 프록시 번들 기반의 주가/검색 라우트를 `stockpeek-proxy/src/worker.js`에 재구성하였다.
- `/api/health`, 차단 상태로 시작하는 `/api/analyze` 추가. Pages Functions 프로토타입은 Worker 진입점이 아니며, Worker는 GitHub push로 자동 배포되지 않는다.
- `stockpeek-proxy/README.md`의 배포 전 바인딩·D1·Secret 검증, 원본 Worker 백업 및 롤백 절차를 적용한다. 현재 실배포·외부 API 라이브 검증은 미완료다.
